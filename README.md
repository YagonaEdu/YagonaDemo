# Yagona Admin — демо без бэкенда

Это автономная копия фронтенда `frontend/` (React 19 + Vite 6) для показа на Vercel.
**Сервера нет:** все запросы к API обрабатываются прямо в браузере мок-слоем
`src/api/` на данных из `src/mocks/`. Ответы повторяют формат Django REST API
(пагинация DRF, фильтры, ошибки 400/403/404), каждый запрос отвечает с задержкой ~300 мс.

Основной проект (`frontend/`, `Backend-main/`) эта папка не использует и не меняет:
у неё свой `package.json`, `package-lock.json` и `node_modules`, импортов из `../` нет.

## Вход

Подойдут любые логин и пароль. Ключевое слово в логине выбирает кабинет
(на странице входа есть кнопки для быстрого входа):

| Логин (пример)             | Кабинет                                  |
| -------------------------- | ---------------------------------------- |
| `owner@registon.demo`      | Владелец центра (все разделы)            |
| `admin@registon.demo`      | Ресепшн / администратор                  |
| `accountant@registon.demo` | Бухгалтер (финансы, зарплаты)            |
| `teacher@registon.demo`    | Преподаватель (Нодира Алиева)            |
| `student@registon.demo` или любой номер телефона | Кабинет ученика (Камола Юсупова) |

Любой другой логин открывает кабинет владельца.

## Что внутри

- `src/mocks/` — генератор демо-данных: учебный центр «Registon Academy» (Ташкент),
  9 сотрудников, ~55 учеников, 10 групп, расписание на ±4 недели от текущей даты,
  посещаемость, счета и оплаты, CRM-воронка, домашние задания, материалы, словари
  и тесты, уведомления, зарплаты.
- Кабинет супер-админа платформы в демо недоступен: ни один логин его не открывает.
- `src/api/` — мок-бэкенд: `index.js` (`mockRequest`, задержка 300 мс), `router.js`,
  `handlers/*.js` (по разделам API), `serializers.js` (формат ответов), `db.js` (хранилище).
- Создание, редактирование и удаление работают и сохраняются в `localStorage`
  (ключ `yagona-demo-db`). Кнопка «сбросить демо-данные» на странице входа
  возвращает исходные данные; через 7 дней данные пересоздаются автоматически,
  чтобы расписание оставалось актуальным.
- Отличия от `frontend/`: `src/services/api/client.js` вызывает `mockRequest` вместо `fetch`,
  `paginate.js` и `utils/format.js` не читают `VITE_API_BASE`, страница входа показывает
  демо-аккаунты, в `vite.config.js` нет прокси на бэкенд. Переменные окружения не нужны.

## Запуск локально

```bash
cd demo-frontend
npm install
npm run dev       # http://localhost:5176
# или продакшн-сборка:
npm run build
npm run preview
```

## Деплой на Vercel

1. Import Project → выбрать этот репозиторий.
2. **Root Directory:** `demo-frontend`
3. **Framework Preset:** Vite
4. **Build Command:** `npm run build`
5. **Output Directory:** `dist`
6. **Install Command:** `npm install`
7. Environment Variables — не нужны.

`vercel.json` в этой папке уже задаёт те же настройки и rewrite всех путей на `/index.html`,
чтобы прямые ссылки вида `/education/registon/students` работали (SPA-роутинг).

Через CLI: `cd demo-frontend && npx vercel` (при первом запуске указать эту папку как корень проекта).
